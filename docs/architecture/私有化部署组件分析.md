## 阅读导航

### 如果你在做最小部署

PostgreSQL 和 Redis 不能省；API 可用 `SERVICE_DISCOVERY_PROVIDER=local` 绕过 Nomad，LaunchDarkly 和 ClickHouse 可以不配置。`2026.30` 起 Orchestrator 不再依赖 Consul（network slot 状态只在进程内），无需为它准备任何组件。

### 如果你在做多节点部署

选择 Nomad 或 Kubernetes 作为 discovery/调度基础；Redis 和 PostgreSQL 必须具备高可用入口。注意 `2026.30` 起上游已移除仓库内官方 Nomad IaC（`iac/`、`self-host.md`），多节点 jobspec 需以 `2026.28` 及更早 tag 的资产为参考自行维护。

### 如果你要部署 Dashboard API

除 PostgreSQL 和 Redis 外，还必须配置 `ADMIN_TOKEN`、`ORY_SDK_URL`、`ORY_PROJECT_API_TOKEN`；Ory issuer 从 `AUTH_PROVIDER_CONFIG` 的 JWT issuer 集合解析（独立的 `ORY_ISSUER_URL` 变量已在 `2026.30` 移除）。

## 总览

| 组件 | 单节点 | 多节点 / HA | 当前无代码替代 |
|------|--------|-------------|----------------|
| PostgreSQL | 必须 | 必须 | 无 |
| Redis | API、Client Proxy 必须 | 必须 | 支持单节点地址或单个 Cluster 引导端点；`2026.30` 起新增 `REDIS_TLS_ENABLED`/`REDIS_PASSWORD` |
| Auth Provider | API Key 场景可不配 | 用户级 JWT/OIDC 时需要 | `AUTH_PROVIDER_CONFIG` 可接外部 issuer；`2026.30` 起管理端点另有 `ADMIN_AUTH_PROVIDER_CONFIG` |
| Ory | 不部署 Dashboard API 时可省 | Dashboard API 必须 | 无通用 profile provider 替代开关 |
| Nomad | 可省 | 官方 IaC 已于 `2026.30` 移除；代码支持仍在 | Kubernetes discovery；`local` 仅单节点 |
| LaunchDarkly | 可省 | 可省 | 未配置时使用源码 fallback |
| ClickHouse | 可省 | 可选 | 未配置时相关写入使用空实现；`2026.30` 起 Loki 也可省（`LOKI_URL` 可选，日志读取经 `logs-read-config` 路由到 ClickHouse） |

> Consul 自 `2026.30` 起不再是 E2B 的组件：上游删除了 Consul KV network slot 存储，Orchestrator 的 slot 状态只保存在本进程内。

## 1. Auth Provider 与 Ory

### 当前能力

- API 和 Dashboard API 从 `AUTH_PROVIDER_CONFIG` 读取 JWT/OIDC issuer 配置；`2026.30` 起管理端点可另配 `ADMIN_AUTH_PROVIDER_CONFIG`。
- 旧的 `SUPABASE_JWT_SECRETS` 不属于 `2026.28` 及之后的配置契约。
- 不配置 `AUTH_PROVIDER_CONFIG` 时，外部 JWT/OIDC 登录不可用；API Key 和 admin token 路径仍由各自 authenticator 处理。`2026.30` 起用户级 `sk_e2b_` access token 已被整体移除（`access_tokens` 表删除、`/access-tokens` API 下线），认证只能走 API Key、JWT/OIDC provider 或 admin 凭据。
- Dashboard API 固定依赖 Ory profile/identity 能力，不能仅用 `AUTH_PROVIDER_CONFIG` 替代。

### Dashboard API 条件

Dashboard API 启动时要求：

| 配置 | 要求 |
|------|------|
| `POSTGRES_CONNECTION_STRING` | 必须且非空 |
| `ADMIN_TOKEN` | 必须且非空 |
| `REDIS_URL` / `REDIS_CLUSTER_URL` | 至少一个 |
| `ORY_SDK_URL` | 必须且非空 |
| `ORY_PROJECT_API_TOKEN` | 必须且非空 |

Ory issuer 不再有独立环境变量（`ORY_ISSUER_URL` 已移除），一律从 `AUTH_PROVIDER_CONFIG` 的 JWT issuer 集合解析。

### 取舍

- 仅内部 API Key 调用、不部署 Dashboard：可不配置外部 Auth Provider 和 Ory。
- 面向用户的 Dashboard：保留外部 OIDC/JWT provider 和 Ory。
- Supabase 可作为外部身份系统之一，但当前部署只能通过通用 provider 配置接入，不能继续使用旧专用变量。

## 2. 服务发现与调度

`SERVICE_DISCOVERY_PROVIDER` 在 `2026.30` 不再有默认值：未设置时 `local` 环境自动使用 `local`，其余环境按 `nomad` 解析（显式设置 `nomad` 与未设置可区分）。合法值为 `nomad`、`kubernetes`、`nomad+kubernetes` 和 `local`。

### Nomad

- `NOMAD_ADDRESS` 默认 `http://localhost:4646`。
- `NOMAD_ORCHESTRATOR_SERVICE_NAMES` 默认 `orchestrator`。
- `NOMAD_ORCHESTRATOR_LEGACY_DISCOVERY_ENABLED` 默认 `true`，用于合并旧 node-pool 回退。
- 省略 `NOMAD_ADDRESS` 不会自动切换到 local provider。

Nomad 是 `2026.28` 及更早版本上游 `self-host.md` 和官方 jobspec 的默认部署路径，同时承担 workload 调度。`2026.30` 起上游移除了仓库内官方 Nomad IaC（`iac/` 目录与 `self-host.md` 一并删除，新部署路径尚未落地）；代码层的 Nomad discovery 与 node pool 调度支持完整保留，自管部署需以旧 tag 的 `iac/modules/` 为参考自行维护 jobspec。API discovery 通过 Nomad native service registration 获取 Orchestrator，再用 gRPC 健康探测筛选节点。

### Kubernetes

使用内置 Kubernetes discovery 时：

`SERVICE_DISCOVERY_PROVIDER=kubernetes`

默认 selector 为：

- Orchestrator：`app.kubernetes.io/name=orchestrator`
- Template Manager：`app.kubernetes.io/name=template-manager`

API ServiceAccount 必须能在目标 namespace 对 Pod 执行 `get`、`list`、`watch`。当前 discovery 从 Pod `HostIP` 组合固定的 `5008` 地址，因此 Orchestrator 和 Template Manager 的部署必须满足 `hostNetwork=true` 及固定端口假设。`2026.30` 新增 `K8S_API_ENDPOINT`：为空时使用 Pod 自身 ServiceAccount（仅集群内有效），设置后可从集群外部经 Google ADC 访问目标集群。

### Nomad + Kubernetes（迁移期）

`SERVICE_DISCOVERY_PROVIDER=nomad+kubernetes` 为 `2026.30` 新增：同时查询 Nomad 与 Kubernetes 并返回去重后的并集，用于 Orchestrator/Template Manager 同时运行在两个平台的迁移期。

### Local

`SERVICE_DISCOVERY_PROVIDER=local`
`LOCAL_ORCHESTRATOR_ADDRESS=127.0.0.1:5008`

local provider 只返回一个静态 Orchestrator，适合本地开发和单节点验证，不是 HA discovery。

### 不存在的 provider

`2026.30` 没有 static-list、Redis 或文件型 discovery provider。新增这类 provider 需要修改 API 配置校验、初始化分支和实现代码，不能通过写一个未定义的环境变量启用。

## 3. Namespace Storage（Consul 已移除）

`2026.30` 起 Orchestrator sandbox network slot 状态只保存在进程内。上游删除了 Consul KV network slot 存储（`storage_kv.go`），`storage_local.go` 中的本机 namespace storage 成为唯一实现，`USE_LOCAL_NAMESPACE_STORAGE` 和 `CONSUL_TOKEN` 变量不复存在。

### 运维含义

- 每台 Orchestrator 独占自己的 slot 分配；所选 CIDR 必须避免与该宿主机、Pod 网络和现有路由冲突。
- slot 状态不跨节点共享；节点替换和遗留 namespace 回收（启动时 reclaim）必须纳入运维流程。
- 私有化部署不再需要部署、维护 Consul，也没有任何服务读取 Consul。

## 4. Feature Flags

当前只内置 LaunchDarkly client 和本地 offline store：

- 配置 `LAUNCH_DARKLY_API_KEY`：连接 LaunchDarkly（`2026.30` 起由共享 Feature Flags 客户端统一读取，不再是各服务 cfg 的字段）。
- 不配置：返回 `flags.go` 注册的 fallback。
- 没有 `FEATURE_FLAGS_PROVIDER`，也没有 YAML 或 Unleash provider。

因此 LaunchDarkly 不是启动必需组件。需要动态灰度时保留它；不需要动态覆盖时使用 offline fallback。`2026.30` 新增 `LOKI_URL` 可选 + `logs-read-config` 路由，使没有 LaunchDarkly 的部署也能把日志读取切到 ClickHouse。当前 117 个 Flag 的名称、类型和默认行为见 [`FeatureFlags私有化部署方案.md`](../feature-flags/FeatureFlags私有化部署方案.md)。

## 5. Redis

### 必需性

| 服务 | Redis 行为 |
|------|------------|
| API | 必须；创建 client 失败会终止启动 |
| Client Proxy | 必须；Sandbox Catalog 固定使用 Redis |
| Dashboard API | `REDIS_URL` / `REDIS_CLUSTER_URL` 至少一个 |
| Orchestrator | 可选；未配置时禁用 Redis event delivery 和 peer registry |

API 和 Client Proxy 不存在内存 catalog 降级，即使是单节点开发也必须提供 Redis。

### 地址契约

- `REDIS_URL`：单个 `host:port`。
- `REDIS_CLUSTER_URL`：单个 Redis Cluster 引导端点，不是逗号分隔列表。
- 两者都配置时，Cluster 配置优先。
- `2026.30` 起 API、Orchestrator、Client Proxy 和 Dashboard API 均支持 `REDIS_TLS_ENABLED` 与 `REDIS_PASSWORD`。
- 应用不支持 Sentinel/Failover client；Sentinel 主从应在前面提供 HAProxy、VIP 或云负载均衡入口。

连接池默认值：

| 服务 | `REDIS_POOL_SIZE` | `REDIS_MIN_IDLE_CONNS` |
|------|-------------------|------------------------|
| API | 160 | 不读取 |
| Client Proxy | 40 | 不读取 |
| Orchestrator | 5 | 2 |

## 6. PostgreSQL 与 Migrations

API 和 Dashboard API 的 `POSTGRES_CONNECTION_STRING` 都是必需配置。正式部署应先运行固定子模块中的 migrator：

~~~bash
make -C infra/packages/db migrate
~~~

PostgreSQL migration tracking 表是 `_migrations`。`2026.28` 及更早的官方 Nomad API job 使用 `infra/packages/db/Dockerfile` 构建的 `db-migrator` prestart task（入口 `./migrator`）；`2026.30` 起官方 Nomad IaC 已移除，migrator 需要自行调度执行。`2026.28` 到 `2026.30` 之间上游新增了 24 个 migration（含删除 `access_tokens` 表、`teams.ory_organization_id`、project limits 与 projection ledger 等），跨版本升级必须先备份并单独执行 migration。

## 7. ClickHouse

`CLICKHOUSE_CONNECTION_STRING` 为空时可不启用 ClickHouse；`CLICKHOUSE_CONNECTION_STRINGS` 使用分号分隔附加端点，并受 `clickhouse-read-endpoint` 和 `clickhouse-write-fanout` Feature Flag 控制。

如果启用本机默认 ClickHouse（`localhost:9000/default`），可运行：

~~~bash
make -C infra/packages/clickhouse migrate-local
~~~

`migrate-local` 的连接串在上游 Makefile 中是固定值。远端或自定义数据库应显式传入服务连接串，并继续使用官方 `_migrations` tracking 表：

~~~bash
GOOSE_DRIVER=clickhouse \
GOOSE_DBSTRING="$CLICKHOUSE_CONNECTION_STRING" \
go -C infra/packages/clickhouse tool goose \
  -table "_migrations" -dir migrations up
~~~

ClickHouse 可用于指标和事件数据，但不是 API、Client Proxy 或 Orchestrator 的核心启动依赖。

## 部署组合

### 单节点验证

至少保留 PostgreSQL 和 Redis，并显式配置：

~~~bash
SERVICE_DISCOVERY_PROVIDER=local
LOCAL_ORCHESTRATOR_ADDRESS=127.0.0.1:5008
REDIS_URL=127.0.0.1:6379
VOLUME_TOKEN_ENABLED=false
~~~

`LOKI_URL` 在 `2026.30` 起是可选项：不设置时 API 没有 Loki 客户端，sandbox/构建日志读取需经 `logs-read-config` Feature Flag 路由到 ClickHouse。禁用 Volume Token 后才可省略四个签名变量。Orchestrator 不再需要任何 Consul 或 namespace storage 相关变量。

### Nomad 多节点

显式设置 `SERVICE_DISCOVERY_PROVIDER=nomad`，部署参考 `2026.28` 及更早 tag 的上游 jobspec（`2026.30` 起官方 IaC 已移除），并为 PostgreSQL、Redis 和对象存储提供生产级高可用。Orchestrator system job 不会在一个节点故障后“迁移到另一台已运行 system allocation 的节点”；节点恢复或被替换后，Nomad 才在符合条件的节点创建 allocation。`nomad+kubernetes` provider 适用于两平台并存的迁移期。

### Kubernetes 多节点

使用 `SERVICE_DISCOVERY_PROVIDER=kubernetes`，确保 Pod label、API RBAC、`hostNetwork`、固定端口和 Service 暴露方式与 discovery 实现一致。Redis、PostgreSQL 和 migrations 的要求不因编排平台改变。

## 可复现核验

在仓库根目录执行：

~~~bash
git -C infra rev-parse HEAD
rg -n 'SERVICE_DISCOVERY_PROVIDER|LOCAL_ORCHESTRATOR_ADDRESS|K8S_API_ENDPOINT' infra/packages/api/internal/cfg/model.go
rg -n 'ALLOW_SANDBOX_INTERNAL_CIDRS|SANDBOX_EGRESS_DSCP' infra/packages/orchestrator/pkg/sandbox/network
rg -n 'ErrRedisDisabled|NewClusterClient|NewClient' infra/packages/shared/pkg/factories/redis.go
rg -n 'ORY_|AUTH_PROVIDER_CONFIG|REDIS_TLS_ENABLED' infra/packages/dashboard-api/internal/cfg/model.go
rg -n 'TEMPLATE_STORAGE_URL|BUILD_CACHE_STORAGE_URL|S3_USE_PATH_STYLE' infra/packages/orchestrator/pkg/cfg/storage.go
~~~

预期提交为 `f32ee8a2a50052f32e3632ceb451111a98dd5104`。这些检查只验证配置契约；实际启动还需要按部署指南准备数据库、对象存储、镜像、Firecracker、内核、busybox 和宿主机权限。
